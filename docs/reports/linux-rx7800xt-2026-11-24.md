# Linux world-rendering integration report — 2026-11-24

## Context

An experimental integration was tested with a user-supplied Xbox Series X
build (version 1.0.2.1) on Linux, Proton Experimental, vkd3d-proton 3.2,
Mesa RADV 26.3.1 and a Radeon RX 7800 XT. Tests used a diagnostics-enabled
release build and separate data and cache directories. The runs were individual
observations, not controlled benchmarks: game progress, compilation and cache
state were not identical. Frame times below are values observed in the window
title, not averages or measurements from the same exact frames.

No game files, shader listings, captured frames or runtime logs are included
in the repository. The figures below are aggregate test results.

After #704, the archive scan's unknown structured-buffer stride refusal

## Automated tests

On the final integration, under Proton, the shader library reported **182
passed, one ignored**, and the GPU library **60 passed, two ignored**. The
synthetic spilled-root-UAV test passed. An all-target Windows/MSVC check
passed after merging #1077; the subsequent merged code compiled for and ran
these test targets and the diagnostics-enabled release executable. These tests
cannot establish that the game's world image is correct.

## Remaining leads

The last run continued to report shader refusals involving lane masks and
computed addresses. It also logged a root UAV write skipped because its
address was not 16-byte aligned. These observations do not by themselves
identify the cause of the black image. The world still needs controlled
in-game comparison, investigation of the remaining shader and resource
failures, and verification of the emitted programs on the target GPU.
